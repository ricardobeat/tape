Who wrote duktape-c3?

A JavaScript engine in C3, built almost entirely by language models across three agent harnesses. Using commit trailers and the harnesses' own session stores, this reconstructs which model wrote which code, how much of it survived, and where a human changed course.

Commit counts throughout are source-only: a commit counts when it changed engine, CLI, or script code. documentation-only commits are excluded so markdown churn doesn't flatter anyone.

Session activity straight from the harness stores, independent of commits. This is the only view that sees models which ran and produced nothing. What the tokens would bill at each provider's published rates. This measures compute consumed, not money spent. Where a harness metered its own usage that number is used; otherwise the rate card is applied.

The project ran itself, in a loop

A large share of the work was not directed task by task. Instead the same self-directing prompt was re-sent over and over, letting the agent pick its own next job from a spec file, do it, test it, and commit. This is the shape of the project's throughput, and it explains why the loop-heavy harnesses show so many messages per commit.

WHO RAN THE LOOPS

Share of each family's source commits that landed within two hours of a loop tick in the same harness. A rough attribution: it counts commits that plausibly came out of a tick, not ones provably caused by it.
