2979dd2 2026-07-10T17:24 [claude-opus-4.8|src/builtins] fix: incref bound args in bound_call re-dispatch to prevent premature free
builtin_bound_call's compiled/BUILTIN_FN re-dispatch path copied the
prepended bound args into the callee's argument register window with raw
TVal assignment. The callee frame takes ownership of those slots and
decrefs them on overwrite/unwind, but the bound args were read out of the

was a net over-decref: a heap value passed as a bound argument (e.g. a

freed while still live. Its pool block was then recycled into the next
bound function, whose `.name = "bound <target>"` write corrupted the
original object — so `Float64Array.name` returned "bound makeArrayLike".

This corrupted nearly every test using testWithTypedArrayConstructors /
testWithAllTypedArrayConstructors (they .bind() each constructor as a
factory arg), plus any bound-function-with-heap-args pattern.

Root-caused with a hardware watchpoint: the victim object's memory was
never written through its own slot; instead its whole pool block was
freed at refcount 0 during a routine LDREG decref, then handed back out.

Fix: incref heap-ref bound args (indices < bound_argc) before writing them
into the callee register window. Appended call args (>= bound_argc) are
moved out of the caller's own registers and need no extra incref.

daf33ec 2026-07-08T18:53 [minimax-m3|src] fix: microtask queue overflow + drop-on-drain — keep async generators alive
The microtask queue held (handler, arg, downstream) triples but the initial
allocation sized the buffer for 16 pairs (32 TVal slots). Once the queue
passed entry 11 — common in any Promise loop body with more than one
reaction — the writes ran past the allocation and corrupted heap memory.

The drain loop then snapshotted and zeroed `microtask_count` before walking
that snapshot. Handlers that resolve another Promise during draining
enqueue new jobs at slot 0, overwriting the still-queued batch and hiding
the original entries from GC.

so new jobs land strictly past the cursor and the whole batch stays GC-visible
until the loop ends. Each microtask triple now lives in 48 TVal slots of
backing memory.

in var_env, but ordinary FUNCTION-class mark logic only looked at the
var_env bindings object — not at the pointer itself — so the saved registers,
async_promise, and other live references were invisible to GC and got
collected while the Promise was still pending. Add an `is_async_state` flag
and a `mark_generator_state` helper used by both the async builtin path and

astral (non-BMP) text was wrong.

surrogate pair before encoding, and each half gets its own independent
3-byte UTF-8 sequence (matches real Duktape's own approach in
duk_unicode_support.c). char_length()/char_at()/char_offset_to_byte_offset()
already counted per leading-byte, so they're correct for free once storage
is canonical — the real work was finding every place that either produces
astral bytes or assumes 1-codepoint-per-unit:

- lexer's `\u{H+}` escape emitter and String.fromCodePoint now emit
  surrogate pairs instead of raw 4-byte UTF-8.
- charCodeAt/codePointAt/.at() were entirely byte-indexed (pre-existing
  bug, not just an astral one — broken for any multi-byte string); now
  route through char_length()/char_at(), with codePointAt combining
  surrogate pairs per spec.

  unit.

  one raw UTF-8 sequence at a time, which under CESU-8 would yield each
  surrogate half separately instead of the combined codepoint per spec
  §22.1.5.1 — now combines a high+low pair into one iteration step.
  Array.from(string)'s separate array-like fallback path (taken because
  the iterator-protocol branch doesn't currently trigger for strings —
  a pre-existing, separate gap) was also byte-indexed; fixed to index by
  code unit for consistency, though it still isn't spec's iterator path.

69e65f8 2026-07-02T01:31 [minimax-m3|test] fix: peephole must skip past and-continuation bridge IF_FALSE

c38c59c 2026-07-02T00:41 [minimax-m3|src/compiler] fix: parse template literals by recursive-descent on the parser side
Template literal parsing had a brittle shared-state machine in the
lexer: a flat `template_brace_balance` counter incremented on every
`{` and decremented on every `}` seen while `IN_EXPR` was active, with
no awareness of which construct opened the brace. As soon as a
substitution contained any nested construct that consumes braces
(function body, object literal, destructuring pattern, block), the
counter drifted and the next `}` was either incorrectly consumed by
the nested construct or prematurely fired `scan_template_after_expr`
mid-expression, leaving the rest of the file unlexed.

Fix: the lexer is now stateless about templates. `{` and `}` always
lex as plain LBRACE/RBRACE. The parser owns the substitution
boundary — after parsing the expression inside `${...}`, it consumes
the closing `}` and explicitly calls `lexer.scan_template_after_expr()`
to obtain the following TEMPLATE_MIDDLE or TEMPLATE_TAIL. This means
the parser's normal recursive-descent brace counting already
distinguishes "this `}` closes the substitution" from "this `}` closes
a nested object literal / function body", with no special-casing.

Removes the now-unused `TemplateState` enum, the
`template_brace_balance` counter, the `template_balance_stack` and
its `MAX_TEMPLATE_DEPTH` cap, and the band-aid save/restore blocks
that had been sprinkled across every speculative parser lookahead
site to undo the lexer's state corruption. Verified by the existing
`test/test_template.js` (27/27), `test/test_b23_fn_tmpl.js`, and
`test/test_b23_combined.js` (6/6 — covers object literals in
substitutions, paren grouping, and function bodies in substitutions).

The other 9 originally-listed failures under B23 are unrelated:
delete/eval/with are strict-only by design, the mod_*.js files need
a module-mode CLI flag, json_stringify_ext and try_hang_test are
separate issues, and test_tostring_tags needs ArrayBuffer (not yet
implemented).
